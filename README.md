# Time Manager

A single-page work-hours tracker. Press **Start** when you begin, **Stop** when you
finish, and the hours land in your phone's browser storage. No account, no server,
no data leaving the device.

**Live:** https://skarphedinnos.github.io/time-manager/

Open that on your phone, then **Add to Home Screen** — installing it is what keeps
the browser from clearing your data, and it launches without browser chrome.

## How it behaves

- **Timer** — the running readout shows the whole unbroken stint, and deliberately
  does not reset at midnight. Pause and resume within a session; paused time never
  counts toward worked hours.
- **Multiple sessions a day** are fine. A session crossing midnight is reported as
  two pieces, one per day.
- **Auto-stop** — a running timer ends at the cutoff (default 22:00). The page can't
  run while closed, so that's applied retroactively when you next open the app, with
  a warning offering an immediate edit. If the app is open when the cutoff arrives,
  it asks "still working?" instead of truncating. A session left *paused* ends where
  the break began, counting only the work before it. Backstop: no session exceeds the
  maximum length (default 16h), which is what catches sessions started late at night.
- **Week and month views** draw each day on a real 24-hour axis — green worked,
  amber paused, plain rest — so a 05:00 start or a late evening is visible at a glance.
  Tap any day to add, edit or delete entries.
- **Profiles** — separate sets of hours (a second job, a test dataset) under
  *Profiles* in the menu. Tap one to switch; tap the active one to rename or delete it.
  Settings and theme are global, so switching profile never changes how the app looks.
- **Backup** — Export hands a JSON file to the share sheet, so it's two taps into
  Drive or Files. Import *merges* by entry id, so importing the wrong file can never
  wipe what's already there.

Hours and sessions read as `7h 30m`; week and month totals as `37.5h`. The week runs
Monday to Sunday. All times follow the device's own timezone.

## Try it with example data

`test-profile.json` holds six weeks of fabricated hours — 33 entries, 5–9 hours on
most weekdays, including a two-session day, a session crossing midnight, one
auto-stopped at the cutoff, and a long midday break.

Easiest way in: **Backup → Load example data**, which fetches the file from the site
itself — no download, no picking the right JSON out of a folder. Importing the file
by hand works too. Either way it names itself `Test profile`, so it lands in its own
profile and leaves your real hours alone. Delete that profile when you're done.

The dates in it are fixed (20 July – 1 September 2026), so most of it sits in weeks
*before* the one the app opens on. A dot on the `‹` arrow means there are entries
further back. Don't regenerate this file if you have already imported it — the entry
ids would change and you would end up with two of everything.

## File format

An export looks like this. `name` decides which profile it merges into — a file
without one merges into whichever profile is active, which is how exports from
before profiles existed still work:

```json
{
  "version": 2,
  "name": "Test profile",
  "settings": { "cutoff": "22:00", "maxSessionHours": 16, "theme": "auto" },
  "sessions": [
    { "id": "…", "start": 1755500400000, "end": 1755529200000,
      "pauses": [ { "start": 1755513600000, "end": 1755515400000 } ] }
  ]
}
```

Times are epoch milliseconds. Importing the same file twice does nothing the second
time — entries are matched by `id`.

## Files

| File | |
|---|---|
| `index.html` | the entire app — markup, styles, logic |
| `manifest.json` | home-screen install metadata |
| `sw.js` | offline cache; network-first for the page, cache-first for assets |
| `icon-*.png` | generated by `tools/mkicon.js` |
| `test-profile.json` | six weeks of example hours, importable as its own profile |

No build step and no dependencies. Edit `index.html`, commit, push — Pages serves it.
